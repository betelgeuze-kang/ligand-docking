# Cross-Family Residual Shadow Layer Plan

This note turns the current single-family GPCR residual work into a **cross-family shadow-layer plan**.

The intent is to keep one governed shell across:

- GPCR
- ion channel
- kinase
- IDP
- non-kinase enzyme (`CA2`)
- nuclear receptor (`PXR`)
- transporter

while staying honest about what each family can support today.

## Current Principle

The global residual layer should expand in this order:

1. prove value on the measured GPCR `100k` failure slice
2. keep ion/kinase on conservative shadow telemetry only
3. add `CA2` and `PXR` as abstaining shadow families once authoritative binder rows exist
4. keep `IDP` limited to feature/state smoothing
5. keep transporter scaffold-only until the expansion workflow is proven on enzyme and nuclear-receptor families

## Why Shadow First

Cross-family promotion should not begin with apply-mode routing.

Instead, the safe order is:

1. frozen baseline
2. shadow telemetry
3. abstaining family-token shell
4. narrow apply-mode where there is measured commercial value

That keeps the commercialization layer auditable and prevents family-specific shortcuts from becoming hidden product logic.

## Family-Specific Stance

### GPCR

- measured `100k` failure exists
- this is where the residual shell must prove value first
- current router decision remains `no_go_for_100k_router`

### Ion / Kinase

- do not force promotion logic here before GPCR improves

### IDP

- keep Kalman-style work in feature/state smoothing only
- avoid coordinate hallucination
- do not let IDP smoothing drive release claims or top-k routing yet

### CA2 / PXR

- use them as the first family-expansion coverage once authoritative binder replacement rows are verified
- keep both in abstaining shadow mode first
- preserve assay-type honesty in provenance

### Transporter

- keep the strongest abstention defaults
- stay scaffold-only until the enzyme and nuclear-receptor workflow is stable
