# Mobile-Lite Development Lane

## Purpose

This lane supports dependency-light development before work moves to a local PC with chemistry, molecular-dynamics, and accelerator runtimes. It covers API schemas, selected read-only route imports, SQLite job accounting, request-security contracts, source compilation, and explicit optional-runtime boundaries.

It does **not** run or validate docking, molecular dynamics, model training, RDKit chemistry, OpenMM, Torch inference, CUDA, ROCm, or HIP behavior.

## Install

```bash
python3 -m venv .venv-mobile
source .venv-mobile/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-mobile.txt
```

The profile intentionally excludes `torch`, `rdkit`, `openmm`, and `h5py`.

## Local checks

```bash
python tools/check_mobile_lite_environment.py
python -m compileall -q \
  api \
  tests/route_compat.py \
  tests/mobile \
  tools/check_mobile_lite_environment.py
python -m pytest -c pytest-mobile.ini --collect-only -q
python -m pytest -c pytest-mobile.ini -q
```

The optional-runtime probes use `pytest.importorskip`, so unavailable heavy runtimes appear as explicit skips rather than collection failures.

## API import boundary

The mobile lane imports and checks:

- `api.models` request/response schemas;
- `api.product_service_contracts` as a dependency-light, read-only router;
- `api.security` middleware contracts;
- `api.job_store` SQLite and redaction contracts.

The lane does not claim that the complete `api.main` execution tree is runnable without the product CPU/chemistry dependencies. Full application, validated-runner, docking, and scientific execution checks remain in the CPU/PC and product-image lanes.

## GitHub-hosted verification

`.github/workflows/ci-mobile-lite.yml` repeats the same dependency-light checks on Python 3.11. The workflow explicitly removes the excluded heavy packages before collection, enforces their absence, runs the mobile suite, and then runs a focused slice of the established API security/job-store regression tests.

## Claim boundary

A green mobile-lite workflow means only that:

- the dependency-light tests collect without Torch, RDKit, OpenMM, or h5py;
- selected API schemas and read-only routes import;
- selected security and SQLite privacy contracts pass;
- heavy optional-runtime probes skip explicitly when unavailable.

It does not demonstrate scientific accuracy, GPU parity, docking readiness, OpenMM correctness, benchmark performance, wetlab evidence, paid-pilot readiness, or broad product readiness. No release or science evidence artifact is regenerated by this lane.
