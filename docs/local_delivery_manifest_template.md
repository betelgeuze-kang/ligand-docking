# Local Delivery Manifest Template

## Purpose

Use this template as the fill-in source for `manifest.json` and `manifest.md` inside a local-delivery bundle. Keep the bundle local-run only and keep the claim scope limited to `kinase`, `ion_channel`, and `gpcr`.

When possible, generate the bundle structure with `python3 tools/build_local_delivery_bundle.py` and use this document to fill the free-text fields consistently.

## Fill Rules

- Fill from the final preflight, final requirements lock rebuild, final queue rebuild, status report, environment manifest, and delivered artifacts.
- Fill the engine provenance record from the exact in-repo engine surfaces used by the run.
- Include the requirements lock generated by the final preflight in the environment provenance.
- If the current preflight, requirements lock, environment manifest, verdict-gate artifact, `current_results_index`, or `partnering_stack` is missing or stale, or the current `accuracy_gate` is `pass=false` at `first_failed_step`, keep the bundle framed as blocked/internal-review and create evidence from the current artifacts first; do not use delivery-ready wording. Treat the preflight as a non-dry-run evidence refresh, not as the delivery-ready verdict.
- Keep `delivery_scope` and `claim_scope` exact. Do not widen them to transporter or to a broad platform claim.
- If transporter appears anywhere, label it `review-only`, `staged`, or `not yet claim-safe`.
- On ROCm, record the actual exported value of `TORCH_BLAS_PREFER_HIPBLASLT` in the environment artifact for routine delivery, preflight, and accuracy bench runs.
- If you intentionally override it for supported-GPU hipBLASLt testing, record the override value in `env vars` / `accelerator env` or the non-default env-var section; do not assume the manifest builder will correct or normalize the process env after the fact.
- Include `local_delivery_verdict_gate` and keep it conservative: it only summarizes the current preflight, requirements lock, environment manifest, nightly, wetlab, queue, status, `current_results_index`, and `partnering_stack` artifacts.
- Keep the `source_artifacts` field list exactly as documented in the gate docs; do not rename or drop fields. The current contract includes the existing gate inputs plus `current_results_index` and `partnering_stack`.
- Record `verdict_gate_fingerprint_check` in both `manifest.json` and `manifest.md`. Set `status=pass`, `ok=true`, `comparison_performed=true`, and `mismatch_count=0` only after the persisted-vs-fresh fingerprint check matches the current bundle/work record across the full source_artifacts label set, including `current_results_index` and `partnering_stack`. If it is false, keep the bundle framed as blocked/internal-review, write the mismatch reason, and do not use delivery-ready wording.
- `runs/local_delivery_verdict_gate_current.json` must report `summary.delivery_ready=true` and its `source_artifacts` fingerprints must match the current bundle/work record, including `current_results_index` and `partnering_stack`, before any delivery-ready wording is used. The final bundle validator must also report `summary.overall_ok=true` and `summary.delivery_ready_policy_ok=true`. If any of those checks is false, keep the bundle framed as blocked/internal-review and do not widen the claim scope.
- If the ROCm run intentionally overrode `TORCH_BLAS_PREFER_HIPBLASLT`, the same override value must be visible in the environment artifact and in the verdict text before delivery-ready wording is used.
- If a family scorecard JSON is bundled, add it to `family_scorecards` with `source_path`, `bundle_path`, `sha256`, and the scorecard summary status; keep blocked scorecards blocked and do not rewrite them into delivery-ready evidence.
- Use the verdict wording from `docs/local_delivery_verdict_template.md` and `docs/local_delivery_claim_policy.md`.
- Keep wording factual and short. Do not add hype, roadmap language, or unsupported generalizations.
- If the workspace was dirty, say exactly which changes were present.

### Known Exclusions

- `optional/deferred API/train/deploy dependencies are not counted as required coverage`
- `runs/nightly_stage6_top_level_reentry_packet_current.md` and `runs/nightly_stage6_top_level_reentry_profile_current.json` are the strict canonical reentry handoff, and they remain supporting-only keep-green evidence rather than a blocker`
- `downstream execute evidence is supporting-only and cannot promote the top-level nightly artifact`
- `nightly stage6 is keep-green and not a representative P0 blocker`
- `commercialization queue is clear for the restricted kinase,gpcr,ion_channel local-delivery scope; keep queue_clear=true and a fresh green verdict before delivery-ready wording`
- `wetlab selected-allatom is green with hard_block_count=0 and atomized parameterization/local-min evidence 7/7; this supports only the restricted delivery verdict`

### Integrity

- `checksums.sha256` is present and covers every file in the bundle except itself and the validator's own `validation.json` / `validation.md` outputs.
- The final bundle validator reports `summary.overall_ok=true` and `summary.delivery_ready_policy_ok=true`.
- The bundle uses the canonical filenames from the local-delivery schema.
- If `family_scorecards` entries are present, the manifest preserves each scorecard's original `summary.scorecard_level_status` and `summary.acceptance_overall_pass`; delivery-ready wording requires every included scorecard to be `pass` and not false on acceptance.
- `verdict_gate_fingerprint_check.status=pass`, `ok=true`, `comparison_performed=true`, and `mismatch_count=0` before any delivery-ready wording is used.
- The verdict gate source artifacts are fingerprinted and match the current bundle/work record before delivery-ready wording is used, including `current_results_index` and `partnering_stack`.
- If `verdict_gate_fingerprint_check.status` is not `pass` or `ok=false`, or if `current_results_index` or `partnering_stack` are absent, stale, or mismatched, the bundle stays blocked/internal-review and the mismatch reason is recorded.
- If the current preflight, requirements lock, environment manifest, or verdict gate artifact is missing, stale, or still incomplete, the bundle stays blocked/internal-review until fresh evidence is captured.

### Verdict

- `Delivery-ready for guarded local validation on the scoped kinase / ion-channel / GPCR workflow documented in this bundle.`
- The local delivery verdict gate should stay narrower than the verdict and should not be described as a proof or a new run.
- If `summary.delivery_ready=false`, the verdict must be negative/internal-review rather than delivery-ready.
- If the bundle is blocked/internal-review, the `verdict_gate_fingerprint_check` result and mismatch reason should be recorded in `manifest.md`.

## Minimum Check

If any of these are missing, the bundle is not complete:

- exact scope
- fresh preflight
- fresh queue
- fresh local delivery verdict gate
- environment snapshot
- requirements lock
- engine provenance
- artifact index
- known exclusions
- rerun command
- scoped verdict
- checksum file for the full bundle
